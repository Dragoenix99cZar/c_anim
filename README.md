# c_anim
> High-Performance Procedural Animation Engine in C

A high-performance, pixel-level procedural graphics and fractal renderer written in raw C. This engine manipulates an uncompressed **RGBA framebuffer** using multi-pass trigonometric fields, domain warping, and escape-time fractal algorithms. 

Designed for **zero-copy interoperability**, the engine compiles into a native, multithreaded command-line pipeline (leveraging **OpenMP** and **SIMD vectorization** for streaming **2.5K/4K video at 60FPS**) or targets **WebAssembly (Wasm)** for high-performance in-browser rendering.

---

## 1. Features & Visual Algorithms

The engine features several distinct algorithmic visual patterns computed per-pixel using spatial coordinates (`x`, `y`) and a time scalar (`frame_count`):

*   **Fluid Plasma (`compute_plasma`):** An intersection of three periodic wave fields (`sin(x)`, `cos(y)`, `sin(x+y)`) creating smooth, shifting organic gradients.
*   **Domain Warping (`compute_warped`):** Complex, turbulent fluid dynamics generated by feeding trigonometric fields back into subsequent spatial functions.
*   **Julia Set Fractal (`compute_julia`):** An animated escape-time complex number algorithm (\(Z_{n+1} = Z_n^2 + C\)) mutatively shifting over time.
*   **Digital Rain Matrix (`compute_matrix`):** Cascading vertical data streams with localized bitwise glitches and fading trail decays.
*   **3D Starfield Projection (`compute_starfield`):** Linear 3D perspective projection mapping coordinate depths into 2D display space with motion blur arrays.
*   **Hypnotic Tunnel (`compute_tunnel`):** Concentric geometric rings utilizing Euclidean distance formulas relative to the frame center.

## 2. Performance Optimization Architecture

### 1. In-Memory Zero-Copy Streaming
Instead of writing millions of intermediate frames to disk (causing storage bloat and hard-drive wear), the engine transforms your terminal pipe into a raw binary data vector channel. It serializes uncompressed RGB24 pixel sequences directly to standard output (`stdout`), feeding video encoders like **FFmpeg** completely in memory.

### 2. Multi-Core OpenMP & Parallel Staging
The pixel canvas calculations are perfectly isolated without cross-frame dependencies. By injecting OpenMP pragmas, the rows are partitioned across every logical core on the system:
*   **Thread Safety:** Multi-core byte sorting is processed inside an isolated `rgb_staging_buffer` array before a single high-speed block thread runs `fwrite` to prevent stream byte scrambling.

### 3. SIMD Hardware Acceleration
By grouping isolated byte copies into structural pointer casts, modern compilers can auto-vectorize memory movements:
```c
*(struct { unsigned char r, g, b; }*)&rgb_staging_buffer[rgb_idx] = 
    *(struct { unsigned char r, g, b; }*)&pixel_buffer[rgba_idx];
```
Compiling with `-march=native` allows the engine to pull raw execution speeds directly from your modern processor architecture (AVX2/AVX-512 instructions).

## 3. Installation & Windows 11 Workflow

### Prerequisites
Ensure you have a modern C compiler (e.g., GCC via MinGW-w64) and **FFmpeg** installed. On Windows 11, you can install them instantly via PowerShell using the Windows Package Manager:
```powershell
winget install MSYS2.MSYS2
winget install Gyan.FFmpeg
```

### 1. Compilation
To activate full multi-core performance optimizations, compile `mainParallel.c` and `app_stream_parallel.c` together:
```powershell
gcc -O3 -fopenmp -march=native -Wall -Wextra mainParallel.c app_stream_parallel.c -o streamerp.exe -lm
```

### 2. Real-Time Interactive Desktop Preview
To watch the multi-threaded rendering live in an interactive canvas window before creating video outputs, pipe your binary data stream straight into `ffplay`:
```cmd
cmd /c "streamerp.exe 9999 | ffplay -f rawvideo -pixel_format rgb24 -video_size 2560x1600 -framerate 30 -i -"
```
*(Note: high-resolution raw environments require `ffplay`-specific arguments: `-pixel_format` and `-video_size` instead of `-pix_fmt` and `-s`).*

### 3. Generate High-Res 2.5K Video Direct to Storage
To render a compressed high-definition H.264 movie file (e.g., 2560x1600 at 30 FPS for 2000 frames) directly in memory, run:
```cmd
cmd /c "streamerp.exe 2000 | ffmpeg -y -f rawvideo -pix_fmt rgb24 -video_size 2560x1600 -framerate 30 -i - -c:v libx264 -pix_fmt yuv420p outputWall.mp4"
```

### 4. Dual Output: Generate Video & Export Individual Source Frames
If you need both the video file and raw individual image assets (e.g., lossless wallpapers), create a target folder (`mkdir frames_output`) and run the dual-output multiplexer:
```cmd
cmd /c "streamerp.exe 2000 | ffmpeg -y -f rawvideo -pix_fmt rgb24 -video_size 2560x1600 -framerate 30 -i - -filter_complex split=2[v1][v2] -map [v1] -c:v libx264 -pix_fmt yuv420p outputWall.mp4 -map [v2] -c:v bmp frames_output/frame_%04d.bmp"
```
